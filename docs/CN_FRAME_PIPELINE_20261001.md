# 采集、发布与自瞄链路改造

新真机日志含20个成功采集帧，全部因来源年龄508–2665ms被HUD拒收，实体呈现日志为0。纯采集低于450ms的10帧仍被随后自瞄规划／写回延迟吞掉。角度写入读回已经有6帧成功，不能再把本次问题归为未进入写入或速度为零。

本次生产路径：

1. `sjzesp_collect → collectLive` 优先采已有候选，独立游标分阶段推进索引发现，不等待完整扫描。索引只存身份和分类，不存或重放旧坐标。
2. Swift在采集返回处结束来源时间，复制不可变实体数组，立即提交主队列。随后读取最新配置，才执行自瞄；保持同一串行内存访问所有权。
3. 自瞄消费带会话／帧／场景／epoch约束的18个世界骨点；只对选中目标重新读骨与相机。世界骨有效掩码独立于绘制投影掩码。
4. 自瞄按阶段刷新实际接触的页，阶段内复用；写后重新解析读回所需页，不清空整个采集工作集。写前检查预算和取消；已经发生的写入必须完成读回和有条件恢复。
5. 普通实体增删和数组迁移读取当前成员集合、移除消失实体；真正世界／角色／控制器／关卡变化仍清空。列表持续变化无法核验时拒收，并明确报告成员校验失败。

热点采样有稳定轮转，避免后半人物饥饿；已确认人物共享首尾字段事务。骨或颜色来源撤销时恢复位置方框。预算让出与读取失败分开记录；超龄批次不重新计时。未延长450ms时效，也未修改cn六行菜单、物资资格或18点算法。

实际检查：22组回归通过（主要C++链ASan/UBSan），源码一致性、Apple arm64 iPhoneOS16.5 SDK语法检查、相关C++ GCC fanalyzer、人工差分与空白检查通过。新增验收含实际1秒模拟阻塞、采集返回后不可变快照不受自瞄修改、取消／重放／只读无写入、世界骨与显示掩码区分、实体增删／地址复用／数组迁移、预算恢复／公平轮转、阶段页刷新／跨页部分完成。所有写入测试均在模拟内存中执行。

单次底层同步读取不能强制中断，预算停止后续读取，不保证硬性返回时间。macOS完整构建见本提交Actions，持续实体呈现和游戏视角响应仍需本次IPA真机验收。旧版本的包体或测试记录不覆盖此次改造。

核对的官方资料：Apple [Dispatch Queues](https://developer.apple.com/library/archive/documentation/General/Conceptual/ConcurrencyProgrammingGuide/OperationQueues/OperationQueues.html)说明异步提交与串行队列执行语义；[CACurrentMediaTime](https://developer.apple.com/documentation/quartzcore/cacurrentmediatime%28%29)说明统一绝对秒时钟。异步提交不保证主队列立即执行，因此交付排队耗时和来源年龄仍实际记录并检查。
